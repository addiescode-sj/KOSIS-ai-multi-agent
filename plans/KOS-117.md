# KOS-117 [진단] 종단 간 성능·병목 진단과 트랙별 우선순위

> TASK.md에 없는 Linear 이슈(M0)다. TASK.md에 T3 줄을 추가하면 `linear_sync.py`가 같은 내용의 이슈를 새로 만들기 때문에 TASK.md는 건드리지 않는다.
> 산출물은 `docs/research/`(plan 게이트 예외 경로)와 Linear 코멘트뿐이고 코드는 바꾸지 않는다.

## Goal
- 완료 기준 (Linear 그대로): 병목 표(지점 · 근거 수치 · 원인 추정 · 담당 트랙)와 트랙별 상위 3개 과제를 이슈에 남기고, 각 과제를 M2·M4 이슈로 연결한다.
- 사용자 추가 기준 (11/05): **결과 리포트의 병목 표를 누구나 이해할 수 있는 형태로 만든다.** 실전 2에서 측정하지 못한 항목(리랭커 preset KOS-113, 첫 토큰 시간 T2-38, 출처 정밀도 T2-39)은 AI 파이프라인 담당(전민기)이 맡으므로 이번 범위에서 뺀다. 표에는 "측정 예정 · 담당"으로만 적는다.
- 데이터 칸: 임도유 코멘트(11/05)로 이미 채워짐 — L0 dimension 미매핑 40.1%, measure 미매핑 35.0%, 로더 표본 195/200. 그대로 가져온다.
- Baseline (실전 2 기록, `../KOSIS-ai-RAG/evals/reports/`):
  - L1 graph:hybrid+cond test 60문항: Hit@1 0.333 · Hit@5 0.483 · MRR 0.389, 실패 노드 retrieve 31 · gate 19, p50 57 ms (T2-36)
  - L1 hybrid+cond-hcx(v3 low): p50 57.5 s · p95 65.8 s / v2 low: p50 10.7 s / gpt-4o-mini p50 1.2 s (T2-09)
  - L2 파서 measures 0.205 · dimensions 0.513 (T2-28)
  - L3 T1-27 regrade: p50 1.49 s · p95 2.63 s, 입력 62,930 토큰 (실전 1 10표 90문항)
  - 1차 리랭커 컨테이너 CPU 25~39 s, backend 이미지 9.96 GB (T2-11)
  - e2e bm25-record → summarize_stat(HCX-DASH-002) 90문항: PASS 25/90, 1위 표 맞음 16/90, 실패 단계 retrieval 64 · understanding 1, p50 0.84 s · p95 22.8 s, LLM 99회·입력 135,852 토큰 (`20261031-204949-T2-15-live-e2e`, phase2 `7048cd7`)
  - **graph(parse→…→gate) + HCX 위에서 e2e를 돈 기록은 없다.**

## Idea
1. 실전 2 기록에서 계층(L0~L4)별 대표 수치·지연·호출·토큰을 한 표로 모은다 (출처 run 경로 포함).
2. (옵션에 따라) 현재 커밋(phase2 `484bd06`, phase1 `e248a45`)으로 빠진 칸을 새로 잰다.
3. 병목 표를 만든다. 읽는 사람이 팀 전체(비개발 포함)이므로:
   - 위에 **질문 하나가 지나가는 길 그림**(parse → retrieve → rerank1 → rerank2 → gate → guide → summarize_stat)을 두고, 각 단계에 "시간"과 "틀리는 비율"을 붙인다.
   - 표 칸: 순위 · 지점(쉬운 이름 + 노드명) · 근거 수치(쉬운 말 "100문항 중 52문항" + 원래 지표) · 원인 추정 · 담당 트랙 · 다음 이슈.
   - 순위 기준은 CLAUDE.md 평가 기준 순서(데이터 정확성 > 예외 처리 > 질의 이해 > … > 지연)를 따르고, 같은 단계면 영향 문항 수가 큰 쪽이 위.
   - 용어 풀이 5줄(Hit@5, p50/p95, 답 없음 판정 등).
4. 트랙별 상위 3개 과제 표(데이터는 임도유 코멘트 그대로, AI 파이프라인·평가·아키텍처·인프라는 이번 표에서 도출) → M2·M4 이슈 링크.
5. `docs/research/KOS-117-bottleneck.md`에 저장, 같은 내용을 Linear KOS-117 코멘트로 올린다.

## Option A — 기록 취합만 (새 실행 없음)
- 접근: 위 Baseline 수치와 임도유 코멘트만으로 병목 표·트랙별 과제를 만든다. e2e·HCX 종단 칸은 "미측정"으로 둔다.
- 예상 성능 향상: 지표 변화 없음(진단 태스크). 다음 단계 영향: M2 우선순위 결정 근거 0 → 1장. 단 수치가 실전 2 시점(T2-29 이전 등)이라 데이터 칸처럼 현재 코드와 어긋난 값이 섞일 수 있다.
- 실질 반영 이점: 평가·아키텍처 트랙의 우선순위 합의 문서, 발표의 "출발점" 슬라이드.
- 비용·리스크: 1~2시간, LLM 비용 0. 이슈 "할 일" 1번(실제 환경 종단 1회 실행)을 하지 못한다.

## Option B — 기록 취합 + 현재 커밋 재측정 (리랭커 제외)
- 접근: A에 더해 이 레포 하네스로 현재 커밋을 다시 잰다. 리랭커(rerank1)는 KOS-113 범위라 끈다.
  - `--layer l012`: L0·L1 필터·L2 한 번에, 오프라인, 비용 0
  - `--layer e2e --retriever graph:hybrid+cond-hcx` 1회 (`HCX_THINKING=none`, 리랭커 끔, summarize_stat는 실전 1 `configs/model.yaml` 모델): 실제 검색 그래프 → 계산까지 L4 판정 + 노드별 지연(`search_spans`) p50·p95·호출 수·토큰 — **graph + HCX 종단 첫 기록**. 실행 하나로 L1 노드 지연과 e2e 정확도를 같이 얻는다(리뷰 4).
  - L3는 재측정하지 않는다: `T1-27-regrade`(p50 1.49 s)를 그대로 쓴다.
  - bm25-record e2e는 기존 `T2-15-live-e2e`를 그대로 쓰고, 새 run과 나란히 둔다(같은 90문항, 검색기만 다름).
- 예상 성능 향상: 지표 변화 없음. 병목 표의 "현재 코드 기준 수치" 칸이 생긴다(L0·L2 + graph-HCX e2e). e2e PASS는 기존 25/90 근처로 예상 — 실패 64건이 검색 단계였고 graph Hit@1(0.333, L1 test)도 bm25와 큰 차이가 없다. 단 L1(test 78문항)과 e2e(L3 골든 90문항)는 분모가 달라 표에 따로 적는다.
- 실질 반영 이점: "검색이 문제냐, 계산이 문제냐"를 같은 커밋의 숫자로 나눠 보여 준다(데이터 정확성·결과 검증). T3-07 단일 에이전트 베이스라인의 비교 기준(전 수치)이 된다.
- 비용·리스크: 2~3시간. HCX 호출 90(rerank2) + summarize_stat 약 100회. 필요한 것: `.env`의 `HCX_API_KEY`·`CHROMA_COLLECTION`, Chroma 서버(:8001), 임베딩 모델(`uv sync --group embed`). T3-00 기록상 Docker 디스크 오류가 있었다 — 환경이 안 뜨면 해당 칸만 "미측정"으로 두고 A로 떨어진다. 마감 11/06 안.

## Option C — 실제 서비스 경로 종단 측정
- 접근: B의 하네스 측정 대신 compose로 서비스 전체(backend · chroma · frontend)를 띄우고, 이 레포 `/chat/stream`(supervisor → search_agent)에 골든 질문을 SSE로 보내 노드 이벤트 시각으로 사용자 체감 지연(첫 이벤트·답 완료)과 컨테이너 자원(CPU·메모리)을 잰다. 정확도는 응답의 표 ID를 골든과 대조.
- 예상 성능 향상: 지표 변화 없음. 하네스가 못 보는 서비스 오버헤드(SSE·컨테이너 CPU·콜드 스타트)를 숫자로 남긴다.
- 실질 반영 이점: 인프라 트랙(이미지 9.96 GB, 컨테이너 CPU) 근거가 생긴다.
- 비용·리스크: 1일+. 측정 스크립트를 새로 짜야 하고(평가 하네스 밖 코드), 첫 토큰 시간(T2-38)과 범위가 겹친다 — 사용자가 뺀 항목. Docker 상태가 불확실. 마감 위험.

## Recommendation
**옵션 B.** 이슈의 핵심 요구(현재 코드로 종단 1회 실행)를 하네스 그대로 채우고, 사용자가 뺀 항목(리랭커·첫 토큰·출처 정밀도)과 겹치지 않는다. 환경이 안 뜨면 그 칸만 "미측정"으로 두는 A로 자연스럽게 떨어져 마감 위험이 작다. C는 T2-38과 겹치고 새 코드가 필요하다.
