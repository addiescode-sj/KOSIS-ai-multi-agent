## Goal
- 완료 기준 (TASK.md): 답변 중 오류(SSE `error`)에 오류 코드 7종(`code`)과 고정 문구(`message`)를 더하고, 화면은 코드로 문구를 고른다. 예외 이름·예외 문구·내부 주소가 화면에 보이지 않는다. 시스템·네트워크 오류(인터넷 끊김, 서비스 연결 실패, 화면 오류, 없는 주소, 새 버전)는 한국어 안내로 바꾼다. 로그 `reason_code`에 오류 코드가 남고, 지금 그래프 노드가 실패 단계 표에 들어간다. pytest·jest·tsc·eslint·build 통과.
- 근거: 팀 결정 11/27 (PM 문서 `kosis-pm/13-오류-유형-정의-초안.md` 9장, 수정 목록 `14-오류처리-수정목록.md`). 2단계(에이전트가 오류를 판단, 처리 시간 상한 60초, 실전 1 거절 문장)는 Linear KOS-211(차주, 담당자)로 뺐다. 핵심 흐름(그래프 노드·실전 1·2)은 고치지 않는다.

## 범위 밖
- 오류 원인을 에이전트(LLM)가 판단하는 것, 처리 시간 상한, 실전 1 거절 문장 → KOS-211.
- 그래프 노드·툴·실전 1·2 코드, 답·거절·되묻기 흐름(`outcome`). 오류일 때만 도는 코드와 표시 층만 바꾼다.
- 입구(Traefik) 안내 페이지·인증서 만료 알림·알림 규칙 → 인프라 작업(김병석, 저장소 `deploy/` 별도).
- 요청 오류(HTTP) code 12종 자체는 바꾸지 않는다(결정 G4). 필드를 더하는 것만.

## Idea
1. **백엔드: 예외 → 오류 코드 변환표** (`backend/app/errors.py` 신규, pytest)
   - `classify(e) -> ErrorCode`: 순서대로 첫 일치.
     | 코드 | 예외 |
     |---|---|
     | `config_error` | `LLMKeyMissing`(실전 1·2 둘 다) |
     | `model_unavailable` | `inference.client.InferenceError`(임베딩·리랭커 서버), `openai.APIConnectionError`(Qwen 서버 연결 거부), `httpx.ConnectError` |
     | `upstream_busy` | `openai.RateLimitError`, 상태 429 |
     | `timeout` | `TimeoutError`, `httpx.TimeoutException`, `openai.APITimeoutError`, 실전 1의 `"model call failed (timeout"` |
     | `upstream_error` | `openai.APIStatusError`(5xx), 실전 1의 `"model call failed (api_error"` |
     | `data_error` | `FileNotFoundError`, `LookupError`(단 `KeyError` 제외: 코드 오류라 `internal_error`) |
     | `internal_error` | 그 밖 |
   - 코드마다 고정 문구와 `retryable` 하나(13 문서 4장 표). `data_error`·`config_error`만 다시 시도하지 않는다.
   - KOS-211이 이 함수를 에이전트 판단으로 바꿀 자리다(입력: 예외, 출력: 코드). 코드 목록과 문구는 그대로 쓴다.
2. **백엔드: 응답에 반영** (`backend/app/main.py`)
   - SSE `error`: `{code, message, retryable, request_id, type, detail}`. `type`·`detail`은 로그·개발용으로 남김(옛 화면 호환). 화면은 쓰지 않는다.
   - 루트 span에 `kosis.error.code`를 남긴다 → 로그 `reason_code`가 읽는다(4).
   - 에이전트를 못 열 때 503: `message`는 고정 문구, `error`에 선택 필드 `cause`(분류한 코드, 예 `model_unavailable`) 추가. code `unavailable`는 그대로.
   - 개발용 `POST /chat` 500: `message`를 고정 문구 + 문의 번호로(예외 문구 제거).
3. **화면** (`frontend/`)
   - `lib/chat/errors.ts` 신규: 코드 → `{title, text}` 목록(답변 중 7종 + 화면이 판단하는 `connection_lost`·`offline`·`network_error`·`backend_unreachable`·`bad_response`). 목록에 없는 코드면 서버 `message`, 그것도 없으면 `internal_error` 문구.
   - `reconnect.ts`·`app/api/chat/route.ts`: `Failure`에 `code`를 싣고 `data-failure`에 넘긴다. 503의 `cause`, SSE `code`를 읽는다. 끊김은 `connection_lost`.
   - `components/chat/chat.tsx` 오류 카드: 코드로 제목·문구를 고르고, 문의 번호(`request_id` 앞 8자리)를 작게. 브라우저 요청 자체가 실패했으면(`data-failure` 없음) `navigator.onLine`으로 `offline` / `network_error`.
   - 인터넷 끊김 알림줄: `online`·`offline` 이벤트로 화면 위 한 줄, 질문 입력 막기, 연결되면 사라짐.
   - 오류 페이지: `app/error.tsx`(화면 오류, `ChunkLoadError`면 "새 버전" 안내), `app/global-error.tsx`, `app/not-found.tsx`. Next.js 16 규칙은 `node_modules/next/dist/docs/`로 확인.
   - 거절 카드: 영어 배지를 배포 화면에서 숨김(개발 환경만), `UNKNOWN_REFUSAL` 제목을 "맞는 통계표를 찾지 못했어요".
   - 서버 `message`를 그대로 보이는 화면(대화 불러오기·피드백·계정·대화 삭제): `errorFrom`이 code를 알면 5장 표 문구로 바꾸는 `userMessage(code, message)` 하나를 두고 쓴다.
4. **로그** (`src/kosis_store/log_rows.py`)
   - `STAGES`에 `candidates`(검색 후보 몫) → search, `understand`·`rewrite`·`rewrite_after_search`(재작성 준비)·`review` → agent.
   - 오류면 `reason_code` = 루트 `kosis.error.code`, 없으면(옛 span) 지금처럼 `error.type`.
5. **문서**: `docs/service/api.md` 2장 `error` 절(코드 7종·문구·재시도 기준), 0장 오류 형식에 선택 필드 `cause`. `docs/log-schema.md`의 `reason_code` 설명. openapi 다시 내보내기(바뀌면).

- 예상 수치: 답변 중 화면에 예외 이름·문구가 나오는 경로 1 → 0, 원인별 안내 1종 → 7종, 오류 코드 pytest 0 → 8건, jest 오류 문구 0 → 4건. 한국어 오류 페이지 0 → 0.
