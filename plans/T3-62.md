# T3-62 배포 설정·인프라 문서 저장소 반영

## Goal
- 완료 기준 (TASK.md 그대로)
  - 공개 저장소에 키·서버 주소·내부 IP가 0건이다.
  - 저장소 설정으로 만든 k8s 결과가 지금 서버와 같다.

## Idea
전민기가 인프라를 이어받는다. 저장소만 받아도 서버를 운영할 수 있게 두 가지를 둔다.
- 지금 서버에서 실제로 쓰는 배포 설정
- 현재 기준으로 다시 쓴 짧은 문서

**모든 옵션에 공통으로 들어가는 것**
- **기준 판:** node-1 `~/deploy`를 scp로 받은 것이다. `.bak*`은 받지 않는다.
  - GPU compose 2개는 11/26에 GPU 서버에 올린 로컬 판(`kosis-infra/deploy/gpu/`)을 쓴다. 같은 내용임은 11/26에 확인했다.
  - CD 세션의 미적용 변경(GHCR)은 넣지 않는다. 그 세션이 이 위에 PR로 얹어, 바뀐 점이 diff로 남게 한다.
- **이번 태스크에서 서버는 바꾸지 않는다.**
  - 서버는 그대로 `~/deploy`로 돌린다. 저장소 판이 같은 결과를 내는지 확인만 한다.
  - 서버를 저장소 판으로 옮기는 일은 CD 세션이 배포 스크립트와 함께 한다.
- **넣지 않는 것**
  - 예전 8001 embed-rerank(`gpu/embed-rerank/`)
  - 덧씌우기 백엔드(`deploy/backend/`). main Dockerfile의 `WITH_EMBED=0`으로 대체됐다.
  - 시험 파일: `k8s-test/`, `gpu/chat_test.py`, `gpu/json_test.py`
  - `31-build-images-mms.sh`
  - CD 세션 스크립트 `60~63`. 그 세션 PR에 넣는다.
- **어느 옵션에서도 올리지 않는 것:** 키, DB 비밀번호, `.pem`, ssh config, `data/`, 가중치.
- **따로 전달할 것 (저장소 밖, 사용자가 직접 넘김):** 채운 주소 파일, `.pem` 키, ssh config.
  - 문서에는 빈칸 예시만 둔다. 예: node-1을 거쳐 node-2·GPU에 접속하는 ProxyJump 설정.
- **커밋 전 유출 검사 (공개 저장소는 이력이 남는다)**
  - 찾는 것
    - `172\.31\.` 같은 내부 IP
    - 점 표기 공인 IP 전체
    - 대시 표기 호스트 `[0-9]+-[0-9]+-[0-9]+-[0-9]+\.sslip`
    - `i-0…`, `sg-…`, 12자리 계정번호
    - `\.pem`, `ssh .*@`
    - `KEY=`·`SECRET=`·`PASSWORD=` 뒤에 실제 값
  - 처리: 한 건이라도 나오면 브랜치를 squash한 뒤에 push한다.
- **민기님 문서 포트:** `docs/service/deploy-inference-split.md`에 "우리 서버는 8002·8003" 한 줄만 단다. 본문은 그 문서 담당자 몫이다.
