# T3-47 e2e 골든 품질 게이트 자동화 + 검수 결과 수정

## Goal
- 완료 기준 (TASK.md 그대로): e2e 골든 품질 게이트(`plans/golden-quality-gate.md`)의 지표를 계산하는 코드가 골든 빌드마다 자동으로 돌아 기준 미달을 알리고, 첫 검수에서 나온 문제(누출·라벨·중복·커버리지·표본 수)를 고친다. 게이트 지표 전→후, pytest
- Baseline (2026-11-20 수동 검수, `plans/golden-quality-gate.md` 2절): Coverage 74.2% · 최소 표본 충족 13/31 · TVD 0.184 · 의도치 않은 중복 17 · 표현 누출 22턴, dev/test 분리 없음 · 라벨 확인 오류 2 · 퇴화 4 · Stale 0

## Idea
1. 게이트 모듈 `evals/golden_gate.py`: 검수 스크립트(scratchpad `audit_golden.py`)를 코드로 옮긴다. 기준값은 한 곳(`GATES`)에 두고 문서 1절과 같게 유지.
   결과는 `evals/datasets/e2e_golden.gate.json`(지표) + 후보 CSV(유사 중복·검수 표본)로 남긴다.
2. 게이트 정책 (리뷰 1·5 반영): **무결성 항목은 막는다(exit 1)** — 의도치 않은 Exact Duplicate, 확인된 누출(test split), 정답 ID·셀 유효성(모호 셀 포함), Stale.
   **분포 항목은 경고만** — Coverage, 유형별 최소 표본, TVD, 미검수 라벨. 막는 항목이 깨지면 빌드가 실패하고, 경고는 표와 meta에 남는다.
3. 자동 실행: `python -m evals.builders.e2e_golden` 끝에서 게이트를 돌린다(`--layer rules`와 같은 골든 파일). verify.sh에는 게이트 계산 로직 단위 테스트(골든 파일은 gitignore라 CI에 없음).
4. 누출 처리 (리뷰 4): 규칙 튜닝 템플릿과 같은 표현의 턴(22)은 새 표현을 만들지 않고 **dev split으로 옮긴다**. 시나리오 해시로 dev/test를 나누되, 템플릿 겹침 문항은 항상 dev. test가 최종 홀드아웃.

후보 수 (2026-11-20, 골든에 쓰인 200만 행 이하 표 303개): 같은 차원 안에 같은 라벨이 다른 코드로 있는 표(same_name 후보) 126 ·
합계와 하위 분류가 있는 수량 표(share 후보) 210 · 비합계 하위 분류 3개 이상(extreme 후보) 298 · 기존 2턴 이월 시나리오(3턴으로 확장 가능) 38 ·
추세 문항(partial_range 거절로 바꿀 수 있는 기간 평균·합계 질문 재료) 83. vague_item·"남자는?"(규칙 판단 보류)·per·unit_mismatch는 후보를 세지 않음 → C.

## Option A — 게이트 + 무결성 수정
- 접근: 게이트(위 2 정책) + 무결성 수정: 22턴 dev 이동·dev/test 분리, 모호 셀 2문항·퇴화 4문항 제외, 주제 전환 두 번째 턴을 단일 문항에 안 쓰인 질문으로(중복 17 → 0). 커버리지·표본은 경고로 남김.
- 예상 성능 향상(게이트 지표): 막는 항목 전부 통과 — 의도치 않은 중복 17 → 0, test 누출 22 → 0, 모호 셀 2 → 0, 퇴화 4 → 0, Stale 0. 경고 항목: Coverage 74.2%(23/31) · 최소 표본 13/31 · TVD 0.184 그대로.
- 실질 반영 이점: 결과 검증(점수 부풀림 제거), 이후 골든 변경이 무결성을 깨면 빌드 실패.
- 비용·리스크: 0.5일. test 문항이 ~30% 줄어든다(dev로 이동) → test 하위 집단 표본이 더 작아짐.
