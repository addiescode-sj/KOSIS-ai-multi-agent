# T3-33 2차 리랭커 모델·서버 설정

## Goal
- 완료 기준 (TASK.md 그대로): 실전 2 PR #48의 `model`·`base_url`을 환경변수(`STAGE2_MODEL`, `Gemma_BASE_URL`)로 서비스·평가에 넘긴다.
  모델 이름에 gemma가 있으면 자체 서버(`Gemma_BASE_URL`·`Gemma_API_KEY`), 아니면 지금처럼. 서비스·평가가 같은 설정 함수 하나를 쓴다, pytest.
- Baseline (코드 확인): `backend/app/config.py:65`·`evals/config.py:36`의 `stage2_llm` 두 벌이 `default_config(name, api_key, thinking)`만 넘김
  → `.env`로 rerank2 모델·서버를 바꿀 방법 0. 실전 2 `3f76487`(PR #48)은 `default_config(model=, base_url=)`를 받는다.

## Idea
`backend.app.config.stage2_llm`에 `STAGE2_MODEL`(모델 이름, 없으면 실전 2 기본)과 gemma 규칙(이름에 gemma → `Gemma_BASE_URL` + `Gemma_API_KEY`,
해석기 `interpreter_chat_model`·실전 1 `STAT_PROVIDER=gemma`와 같은 규칙)을 넣고, `evals.config.stage2_llm`은 그 함수를 부른다(구현 하나).
`base_url`은 실전 2에서 provider openai(STAGE2=gpt)일 때만 쓰인다.

## Option A — 서비스 config 한 곳 + gemma 규칙 (Gemma_* 재사용)
- 예상: rerank2 모델·서버를 `.env`로 바꿀 수 있는 경로 0 → 1, stage2 설정 구현 2 → 1. 검색 수치는 설정을 바꿀 때만 바뀜(기본값 그대로).
- 이점: 자체 Gemma 서버 변수를 실전 1·해석기·rerank2가 같이 씀. 비용·리스크: 작음. gemma가 아닌 이름의 vLLM 모델은 서버를 못 고름.
## Option B — 전용 변수 (`STAGE2_BASE_URL`·`STAGE2_API_KEY`)
- 예상: A와 같음 + 모델 이름과 무관하게 서버 지정. 이점: 유연. 리스크: 같은 서버 주소를 변수 두 곳에 적어야 함.
## Option C — 모델 이름 → (서버, 키) 표
- 예상: A와 같음. 이점: 서버 여러 개. 리스크: 지금 서버는 하나라 과함.

## Recommendation
A. 사용자가 지정한 변수 이름(`STAGE2_MODEL`, `Gemma_BASE_URL`)이 A다.
