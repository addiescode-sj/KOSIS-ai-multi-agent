# T3-34 복합 질문 채점 기준 Complete@2 (실전 2 PR #49 반영)

## Goal
- 완료 기준 (TASK.md 그대로): 실전 2 PR #49의 복합 질문 채점 기준(모든 슬롯이 2위 안 = Complete@2)을 이 레포 `evals/` 사본에 옮긴다. Hit@k·MRR 정의는 그대로, L1 리포트의 Complete 타일·슬롯 칩·qtype 표가 2위 기준을 쓴다, pytest
- Baseline: L1 staged-hcx(`evals/reports/20261110-165052-bump-after-l1-graph-staged-hcx`, test 60문항) Complete@3 = 80.0%(48/60), multi_table 28.6%(2/7). Complete@2 지표 없음

## Idea
submodule은 이미 `f569721`(PR #49)로 올렸다. 이 레포는 실전 2 `evals/`를 쓰지 않고 자체 사본(T3-00)을 쓰므로 같은 diff를 사본에 손으로 옮긴다.
옮길 곳(실전 2 diff와 1:1, grep으로 하드코딩 전부 확인):
1. `evals/evaluators/retrieval.py:15` `KS`에 2 추가
2. `evals/tasks/l1_retrieval.py:66` qtype 표 열: `complete@3` 앞에 `complete@2`를 끼워 넣는다(`complete@3` 열은 그대로 둔다 → 옛 리포트와 비교 유지)
3. `evals/report_html.py:198` 타일 Complete@3 → Complete@2, `:213` 슬롯 칩 ✓ 기준 `rank <= 5` → `<= 2`, `:229` 안내 문구 "✓ 2위 안 · △ 3~10위"
4. `tests/test_evals_metrics.py` 실전 2와 같은 assert 2줄
측정: 기존 `run_eval --layer l1 --from-run <staged-hcx run>`(T3-22 재채점 경로)으로 저장된 순위를 같은 `score_item`으로 다시 채점한다. 검색 재실행·LLM 비용 0이고 ops_history에도 남는다.
미리 계산한 값(같은 골든셋 sha256 `0e73269f…`, test split): Complete@2 = 73.3%(44/60), multi_table 28.6%(2/7, Complete@3과 같음).

## Option A — PR #49 그대로 이식 + `--from-run` 재채점
- 접근: 위 4곳만 고친다. 측정은 `--from-run` 재채점 1회
- 예상 성능 향상: 지표 정의 변경이라 시스템 성능은 그대로. 대표 타일 Complete@3 80.0% → Complete@2 73.3%(엄격해짐, 미리 계산함). multi_table은 2/7 → 2/7
- 실질 반영 이점: 결과 검증 — 실전 2와 같은 채점 기준이라 두 레포 L1 수치를 바로 비교할 수 있다. `--from-run`이 ops_history에 Complete@2 기준점을 비용 0으로 남긴다
- 비용·리스크: 30분, LLM 비용 0. 옛 리포트와 타일 이름이 달라지지만 qtype 표에 `complete@3`이 남아 비교할 수 있다

## Option B — A + 현재 pin으로 L1 재실행
- 접근: A에 더해 `run_eval --layer l1`(staged-hcx)을 현재 submodule(`f569721`)로 다시 돌린다
- 예상 성능 향상: A의 정의 변경 + 11/10 이후 실전 2 변경(PR #48 프롬프트 v4 등)이 반영된 최신 수치
- 실질 반영 이점: 검색 코드 최신 상태의 기준점
- 비용·리스크: HCX로 L1 전체 1회(30~60분·토큰 비용). PR #48 효과와 지표 변경이 섞여 "몇 → 몇"의 원인을 나누기 어렵다(A를 먼저 하면 분리됨)

## Option C — 대표 타일 Complete@3 유지 + Complete@2 타일 병기
- 접근: KS·qtype 표·테스트는 A와 같게 하고, 리포트 타일은 Complete@3을 남긴 채 Complete@2를 옆에 추가한다. 슬롯 칩 기준만 2위로 바꾼다
- 예상 성능 향상: A와 같은 수치(73.3% 추가 표시, 80.0% 유지)
- 실질 반영 이점: 옛 리포트와 타일까지 그대로 비교된다
- 비용·리스크: 실전 2 리포트와 타일 구성이 달라진다(요청 "같은 채점 기준"에서 조금 벗어남), 타일 1개 증가

## Recommendation
옵션 A. 요청이 "실전 2와 같은 채점 기준"이고, `--from-run` 재채점으로 LLM 비용 없이 기준점을 남긴다. 옛 비교는 qtype 표의 `complete@3` 열로 충분하다.
