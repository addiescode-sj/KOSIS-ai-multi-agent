# 골든셋 품질 게이트 (e2e 골든)

평가 결과를 믿으려면 먼저 평가셋을 믿을 수 있어야 한다. 이 문서는 e2e 골든셋(`evals/datasets/e2e_golden.jsonl`, T3-46)이
통과해야 할 품질 기준, 각 지표를 재는 방법, 2026-11-20 첫 검수 결과, 고칠 일을 정리한다.
기준값은 통계적으로 확립된 합격선이 아니라 **팀이 합의해서 조정하는 운영 정책값**이다. 바꾸면 이 문서와 게이트 코드를 같이 고친다.

- 대상: `e2e_golden.jsonl` 601 시나리오 · 694턴 · 312표 · 14조사 (+ 숫자 정답 `e2e_golden_calc.jsonl` 544개)
- 만드는 법·라벨 정의: `evals/README.md` "e2e 전용 골든셋", `plans/T3-46.md` "정답 라벨"
- 자동화: T3-47 (`plans/T3-47.md`) — 골든을 빌드할 때마다 이 게이트가 돈다

## 1. 기준 (운영 정책값)

| 검사 항목 | 기준 | 왜 |
|---|---|---|
| 필수 시나리오 Coverage | 100% | 평가하겠다고 정한 유형이 하나라도 0건이면 그 능력은 측정되지 않는다 |
| 주요 질문 유형별 최소 표본 | 유형마다 20개 이상 | 15개면 정확도 1문항 차이가 6.7%p라 전→후 비교가 흔들린다 |
| 사용자 분포와의 TVD | 0.10 이하 | 평가셋 유형 비율이 실제 질문과 다르면 전체 평균이 서비스 품질을 대표하지 못한다 |
| 의도하지 않은 Exact Duplicate | 0건 | 같은 문항을 두 번 채점하면 그 문항의 성패가 두 배로 반영된다 |
| 확인된 최종 테스트 누출 | 0건 | 규칙·프롬프트가 본 문장으로 평가하면 점수가 부풀려진다 |
| 정답 검증 | 정답 ID 전수 유효성 검사 | 없는 표·바뀐 파일·모호한 셀을 가리키는 정답은 채점을 틀리게 만든다 |
| 정답 라벨 품질 | 독립 검수, 불일치 해결 | 정답이 틀리면 맞는 답을 오답으로 센다 |

### 무엇을 오염으로 보는가

같은 표를 쓰거나 비슷한 문장이라고 모두 오염은 아니다.
"2024년 서울 인구"와 "2023년 서울 인구"는 같은 표지만 서로 다른 기간을 찾는 능력을 재는 유효한 문항이다.
반대로 표현만 바꾼 같은 평가 사례가 많으면 그 유형이 과대대표되어 점수가 부풀려진다. 판정 기준은 "다른 능력을 재는가"다.

| 문제 유형 | KOSIS에서 생기는 예 | 검증 방식 |
|---|---|---|
| Exact Duplicate | 같은 질문이 골든셋에 반복 | 정규화(NFKC·소문자·공백·문장부호 제거) 후 해시 비교 |
| Near Duplicate | "서울 인구는?" / "서울의 인구를 알려줘" | 문자 2~4gram TF-IDF 코사인 0.85 이상 후보 → 수동 검토 (+ 같은 정답 셀·같은 유형) |
| Test Leakage | 골든 질문을 보고 규칙·프롬프트를 맞춤 | 서비스 코드·프롬프트에 골든 문장이 있는지, 규칙 튜닝용 템플릿과 같은 표현인지, dev/test 분리 |
| Answer Leakage | 정답 표 ID를 검색 단계 힌트로 전달 | 평가 러너가 그래프에 넘기는 입력, 서비스 코드가 골든 파일을 읽는지 감사 |
| Label Error | 정답 셀·값이 틀리거나 모호 | 정답 셀을 Parquet에서 다시 읽어 대조, 셀 ID 유일성, 파생값 재계산, 독립 재라벨링 표본 |
| Stale Data | 통계표 폐기·개편으로 정답 무효 | 표 키가 카탈로그에 있는지, Parquet 해시가 골든을 만들 때와 같은지 |

### 지표 정의

| 지표 | 계산 | 관리 |
|---|---|---|
| Exact Duplicate Rate | 의도하지 않은 중복 채점 문항 / 전체 시나리오 | 0% 목표 (후속 질문의 맥락용 첫 턴 재사용은 의도된 중복으로 따로 센다) |
| Near Duplicate Rate | 검토 후 불필요한 의미 중복 / 전체 시나리오 | 후보는 자동, 판정은 사람 |
| Verified Leakage Rate | 누출이 확인된 문항 / 전체 | 최종 홀드아웃(test)에서 0% |
| Label Error Rate | 검수에서 틀린 정답으로 확인된 문항 / 검수 문항 | 고친 뒤 재평가 |
| Stale Reference Rate | 무효 정답 참조 / 전체 참조 | 평가 시점 기준 0% |

### 어려운 하위 집단을 따로 본다

전체 평균은 높아도 특정 상황에서는 성능이 크게 낮을 수 있다(예: 전체 Hit@5 85%인데 다중 조건 질문은 50%, 모호한 질문의 적절한 되묻기는 40%).
그래서 리포트는 항상 **하위 집단별 문항 수 · 비중 · 성능**을 함께 낸다. 하위 집단이 20개 미만이면 그 수치는 참고값으로만 읽는다.

## 3. 고칠 일 (T3-47)

1. 누출·라벨: 후속 질문 표현을 규칙 튜닝 템플릿과 겹치지 않게 바꾸기, dev/test 분리(최종 홀드아웃), 모호 셀 2문항·퇴화 4문항 제외
2. 커버리지: 빠진 8개 유형 문항 추가
3. 최소 표본: 20개 미만 유형을 20개 이상으로
4. 중복: 주제 전환 두 번째 턴을 단일 문항과 다른 질문으로
5. 분포: 답 없음·다중 표를 늘리고 기간 문항 비중을 낮춰 TVD를 0.10 아래로
6. 자동화: 위 지표를 계산하는 게이트가 골든 빌드마다 돌고, 기준 미달이면 빌드가 알린다

## 4. 사람이 해야 하는 것

- 독립 재라벨링 표본 검수 (5문항마다 1개 + 규칙 불일치 문항, 검수 CSV의 `ok`·`note`)
