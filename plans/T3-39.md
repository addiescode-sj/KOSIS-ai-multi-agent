## Idea
채점 규칙(판정)은 바꾸지 않고 입력·집계만 고친다. 저장된 run 재채점으로 전→후를 잰다(LLM 호출 0).

## Option A — 채점기·집계만 수정 (선택)
- `read_cells(path, refs)`: 골든 사실·답의 셀만 pyarrow 배치 스트리밍으로 읽기. 턴 기록에 `tokens_by_model`, `ops`가 모델별로 단가 곱(통화 섞이면 합계 없음).
  `runners/stat.read_rows`로 l3·e2e 재채점, e2e 행에 전체 순위 `keys` 저장. 검색 골든을 qid → phase1_id → 질문 원문으로 연결. 빌더 split = dev.
- 예상: 큰 표 29문항 채점 가능, e2e 정답 표 판정 문항 0 → 10, 비용 합계 경로 0 → 1.
