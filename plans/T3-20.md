# T3-20 ⭐ 평가 리포트 HTML 전 계층

## Goal
- 완료 기준 (TASK.md 그대로): 모든 `run_eval` 실행(l0·l1·l2·ablation·l012·l3·e2e·agent)이 report.html을 남긴다: 평가 결과, 운영 지표(지연·토큰·비용·실패율),
  trace별 측정(턴·문항마다 span 경로·지연·Jaeger 링크)을 읽는 법과 함께
- 요청 (사용자, 2026-11-06): "평가 돌릴 때마다 html로 실제 평가 결과와 운영 지표, trace별 측정 결과를 이해하기 쉬운 형태로"
- Baseline: report.html이 생기는 계층 **3/8** (l1·l3·e2e, `evals/report_html.py`). l0·l2·ablation·l012·agent는 report.md만
  (`run_eval.py:622` `ponytail: l0/l2/ablation write report.md only`). agent 턴 기록에는 span별 시간이 없음(툴 호출 목록·턴 지연만).

## Idea
기존 `evals/report_html.py`(자체 포함 HTML, 인라인 SVG, 다크 모드, 운영 지표·추이·trace 칩·Jaeger 링크)를 넓힌다. 새 라이브러리 없음.
세 옵션 공통 (리뷰에서 찾은, 지금 코드로는 깨지는 곳):
1. `run_eval.main`이 모든 계층에서 `report_html.write(out)`를 부른다(docstring은 이미 그렇게 말함).
2. `render()`를 계층 모양에 맞춤: l012 manifest의 골든은 `{"l0·l1", "l2"}` 두 개, `ops`는 계층별 dict(`l0`·`l1-gold`·`l1-pred`·`l2`),
   추이는 `ops_history`의 같은 이름 계층으로 찾는다. 행 ID는 `qid` / `key`(l0) / `sid#run·turn`(agent).
3. 결과 표 상한: l0 2364행, l012 약 5.3천 행 → 표는 실패·주의 행 우선 200행까지, 나머지는 건수만(전체는 results.jsonl).
4. trace별 측정이 없는 계층(l0·l2·ablation: span 없음, 지연은 0 또는 함수 시간)은 "trace 없음"으로 명시.
5. 섹션마다 "읽는 법" 한 줄(지표 뜻, 좋은 방향).
- agent trace: `turn_record`에 span 목록(이름·시작 ms·길이 ms·상태) 추가 — 노드·툴·LLM 호출 span만 열리므로 턴당 수 개~십수 개.
  span이 있는 건 `--agent` 실제 실행뿐이다(oracle·옛 run 재채점은 "span 없음"으로 표시).
  Jaeger 링크: agent run은 OTLP가 설정됐을 때만 manifest에 `jaeger`(서비스 `kosis-agent-evals`)를 기록해 링크를 건다.
- 테스트: 계층별 합성 run 폴더로 render pytest, 실제 run 폴더(KOS-117 l012, T3-06 패리티 l012)로 렌더 확인.

## Option A — 공통 요약 화면 + agent 대화·trace 화면 (추천)
- 접근: 공통 1~5 + l0·l2·ablation·l012는 **공통 요약 본문**(summary 숫자를 타일, report.md의 표를 HTML 표로, 읽는 법, 운영 지표, 상한 있는 결과 표).
  agent는 **전용 화면**: 지표 타일(대화 성공률·pass^k·툴 선택·파라미터·상태·수치·근거 없는 숫자), 빠진·불필요 호출(툴별), 인자 필드별 정확도,
  처음 실패한 턴 분포, 대화별 화면(턴마다 질문 → 툴 칩(인자·결과 툴팁) → 답, 판정·오류, 지연·토큰), 턴별 span 워터폴과 Jaeger 링크.
- 예상 효과: report.html이 나오는 계층 3/8 → 8/8. trace별 측정이 있는 계층 l1(그래프)·l3·e2e → + agent(`--agent` 실행의 모든 턴). l0·l2·ablation은 trace 없음(측정 대상 아님).
- 실질 반영 이점: 결과 검증. T3-07~10이 비교하는 것이 agent run이라 그 화면에 공을 들인다.
- 비용·리스크: 1일 미만(공통 본문은 md 표 재사용, 새 차트는 agent만).

## Option B — A + l0·l2·ablation 전용 차트
- 접근: A + l0 필드별 채움률 막대(전체 vs 골든), l2 필드별 정확도 막대(split별)·P/R·틀린 문항(정답 vs 예측), ablation 조합별 recall·후보 수 막대와 슬롯 판정 표.
- 예상 효과: A와 같음 + 검색 계층 결과를 그림으로. 지표 값 변화 없음.
- 실질 반영 이점: 데이터 트랙 발표 자료. 단, 지금 이 계층들을 발표·비교하는 일정이 없음(기존 `ponytail: add charts when they are presented`).
- 비용·리스크: A + 반나절~1일. `report_html.py`가 크게 늘어남.

## Option C — B + 실행 목록·비교 페이지
- 접근: B + `evals/reports/index.html`(모든 run의 계층·stage·핵심 지표·링크)과 같은 계층 두 run의 지표 차이·뒤집힌 문항/대화.
- 예상 효과: B와 같음 + 전→후 비교가 한 화면.
- 실질 반영 이점: "무엇을 바꿔서 몇 → 몇"을 바로 뽑음, T3-10 비교 표의 바탕.
- 비용·리스크: 2일+. 비교 가능 조건(같은 골든 해시만 등)을 새로 정해야 함. T3-07 베이스라인 전엔 비교할 agent run이 없음.

## Recommendation
**옵션 A.** 요청의 "모든 실행에 HTML"과 "trace별 측정"을 모두 채우는 가장 작은 안이다. trace가 있는 계층(l1·l3·e2e·agent) 중 비어 있던 agent에 전용 화면을 만들고,
trace가 없는 l0·l2·ablation은 읽는 법이 붙은 공통 요약으로 충분하다. B의 전용 차트는 그 계층을 발표할 때, C의 비교 페이지는 T3-07 베이스라인 뒤에 한다.
