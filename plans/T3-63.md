# T3-63 운영자 화면 목업을 Next.js 프론트 `/admin`에 React·Tailwind 컴포넌트로 퍼블리싱

## Goal
- 완료 기준 (TASK.md 그대로): 디자인 목업(Pencil `KOSIS.pen` → Vite 목업 `localhost:5173/admin`)의 운영자 화면 3개(메트릭 대시보드·필터 설정·Jaeger 분산 추적)를 `frontend/`의 `/admin` 라우트에 React(TSX)·Tailwind 컴포넌트로 옮긴다. 데이터는 예시 값이고 API는 연결하지 않는다. 목업과 화면 차이 0(눈으로 비교), tsc·eslint·jest·next build 통과.
- Baseline: 프론트의 운영자 화면 0개. 목업은 `Admin.jsx` 한 파일(182줄, JSX, 타입 없음)에 화면 3개가 들어 있다.

## 배경·제약
- 실제 운영자 페이지는 T3-57의 별도 앱 `admin/`(Jinja, 8100)이다. 배포 입구(`deploy/k8s/40-ingress.yaml`)가 `/admin`을 그 앱으로 보낸다.
  그래서 이번에 만드는 Next.js `/admin`은 **배포 주소에서는 보이지 않고**, 로컬 프론트(3000)에서만 열린다. 입구 설정과 T3-57 앱은 바꾸지 않는다.
- 예시 숫자가 진짜 지표처럼 보이면 안 된다(데이터 정확성 원칙). 화면 머리에 "예시 데이터" 표시를 둔다.
- 토큰은 이미 같다: `globals.css`에 목업과 같은 brand·canvas·line·ink·sub·mute 색이 있다. 차트는 프론트에 이미 있는 Recharts를 쓴다.

## Idea
1. `app/admin/layout.tsx`(사이드바·헤더 셸) + `app/admin/page.tsx`(대시보드) · `filters/page.tsx` · `jaeger/page.tsx`. 목업의 hash 라우터 대신 Next 라우트, 사이드바 활성 표시는 `usePathname`.
2. `components/admin/`에 화면 조각을 나눈다: 셸(sidebar·header), stat-card, bar/area/donut 차트, heatmap, data-table, reason-bars, 필터 폼.
3. 예시 값은 `lib/admin/sample.ts` 한 곳에 타입과 함께 둔다(화면은 값을 받기만 한다).
4. 탭·기간·사용자 구분·토글은 화면 상태만 바꾼다(값은 그대로, 예시이므로).
5. Playwright로 목업(5173)과 새 화면(3000)을 같은 크기로 찍어 비교.

## Option A — 목업 그대로 정적 퍼블리싱
- 접근: 위 Idea 그대로. 예시 값의 모양은 목업 기준.
- 예상 성능 향상: 프론트 운영자 화면 0 → 3. 에이전트 지표(정확도·지연)에는 영향 없음.
- 실질 반영 이점: 기능 완성도·발표 자료(운영자 화면 시연). 컴포넌트는 나중에 실제 데이터로 바꿀 때 그대로 쓴다.
- 비용·리스크: 반나절. 배포 주소에서는 Jinja 앱이 보이므로 두 운영자 화면이 공존하는 혼란 — README·plan에 적어 둔다.

## Option B — 겹치지 않는 주소 `/preview/admin` + 배포 차단
- 접근: A와 같은 컴포넌트를 `/preview/admin`(·`/filters`·`/jaeger`)에 둔다. 실제 `/admin`(T3-57)과 주소가 겹치지 않는다. 배포 빌드에서는 `notFound()`로 막고(`NODE_ENV=production`이면 404), 로컬 개발 서버에서만 연다.
- 예상 성능 향상: 화면 수 A와 같음. 운영자 화면 두 개가 같은 주소를 두고 헷갈릴 일 0.
- 실질 반영 이점: 예시 숫자가 배포 사이트에 나갈 위험 0(데이터 정확성). 진짜 운영자 앱과 역할 구분이 분명하다.
- 비용·리스크: A와 거의 같다(가드 1곳). 요청한 주소(`/admin`)와 다르다. `next start`(배포 모드)로는 볼 수 없어 시연은 `next dev`로 해야 한다.

## Option C — 실제 데이터 연결
- 접근: 백엔드(또는 admin 앱)에 지표 JSON API, 프론트 BFF·zod 검사, 운영자 허용 목록 로그인, 입구 설정 변경까지.
- 예상 성능 향상: 실제 지표를 React 화면으로 봄. 
- 실질 반영 이점: 기능 완성도 최대.
- 비용·리스크: 1~2일 이상. T3-57(김병석) 앱과 역할이 겹치고 배포 입구를 바꿔야 해 팀 합의가 먼저다. 이번 요청("API는 연결하지 않음") 범위 밖.

## 작업량 근거·공통 사항
- 옮길 것: 셸 1(사이드바·헤더) + 화면 3 + 조각 9(stat-card, bar-chart, area-chart, donut, heatmap, data-table, reason-bars, metric-tile, filter-form). 기존 `components/ui`의 badge·button·card·chip을 쓰고, select·toggle은 새로 만든다. 한 파일 한 컴포넌트.
- 공통: 모든 화면에 "예시 데이터" 표시, `robots: noindex`, 고객 화면 내비에는 링크를 두지 않는다. `cacheComponents` 설정에서 `usePathname` 사이드바는 client 컴포넌트로 분리.
- 측정: 목업(5173)과 새 화면을 같은 크기(1440×900)로 찍어 눈에 띄는 차이 개수(전 → 후)를 Result에 남긴다.

## Recommendation
옵션 B. 요청은 `/admin`이지만 배포 입구가 `/admin`을 T3-57 앱으로 보내 A의 화면은 배포에서 어차피 보이지 않고, 예시 숫자가 진짜 지표 화면처럼 섞일 위험만 남는다. B는 비용이 같고 그 위험이 없다. 요청 주소를 꼭 지켜야 하면 A.

## Decision
- 2026-11-27 사용자 선택: **옵션 B** (`/preview/admin`, 배포 빌드에서 404).
- 추가 요구: "고객 화면과 같은 방식"으로 만든다 — `frontend/AGENTS.md` 규칙대로 TanStack Query(서버 prefetch + `HydrationBoundary` + `useSuspenseQuery`), 키는 `lib/query/keys.ts`, 응답은 zod로 런타임 검사, API 호출은 `lib/admin/` 모듈, 한 파일 한 컴포넌트, `components/ui` 재사용.
- 예시 데이터는 BFF 라우트 핸들러(`app/api/preview/admin/...`)가 돌려주고 화면은 쿼리로 읽는다. 나중에 실제 지표 API가 생기면 핸들러만 바꾼다. 핸들러도 배포 빌드에서는 404.

## Result
- 화면: 프론트 운영자 화면 0 → 3 (`/preview/admin` 메트릭 대시보드, `/filters` 필터 설정, `/jaeger` 분산 추적). 컴포넌트 `components/admin/` 19개(한 파일 한 컴포넌트), 데이터 층 `lib/admin/` 7개, 라우트 핸들러 2개.
- 고객 화면과 같은 방식: 서버 prefetch(기다리지 않음) + `HydrationBoundary` + `useSuspenseQuery`, 키는 `lib/query/keys.ts`, 응답은 zod(`AdminDashboard`·`AdminTrace`)로 검사, 실패는 값으로 돌려 화면 하나로 보여 줌. 필터는 주소(`?period=&user=&internal=`)에 두어 필터 화면·새로고침·링크가 같은 숫자를 보여 줌.
- 목업 대비 차이(1440×2900 스크린샷 비교): 의도하지 않은 차이 1 → 0(TTFT 칸 간격 2px 고침). 의도한 차이 3: 헤더 "예시 데이터" 표시, 음수 변화량은 내려가는 화살표(목업은 색만 다르고 화살표는 늘 위), 필터 화면 헤더에 배치 상태 없음(배치 상태는 대시보드 데이터).
- 숫자는 코드가 만든다: 이유별 비율·거절 합계(도넛 가운데)·단위·부호는 표시할 때 계산. 예시 값끼리 맞는지 테스트(답 유형 합 = 총 질문 수 2,841, 거절 사유 합 = 거절 182, 마지막 날 = 오늘).
- 배포 차단: `next build` + `next start`에서 `/preview/admin`·`/filters`·`/jaeger`·API 모두 404, 페이지 HTML에 예시 숫자 0건. 처음에는 layout `notFound()`만으로 404 화면이 200 상태로 나와 `next.config.ts` `rewrites.beforeFiles`(production에서만)로 막음. dev(3200)에서는 200.
- 검사: tsc 통과, eslint 0, jest 101 → 104(admin 3개), next build 통과. 화면 동작: 기간 선택 → 주소·부제 바뀜, 표 검색 1건으로 좁혀짐, 필터 화면 기본값 → 적용 → 대시보드로 돌아옴, 추적 화면 span 6개.
