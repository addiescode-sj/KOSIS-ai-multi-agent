# T3-50 운영 지표에 요청당 비용 추가 — 모델별 토큰 단가

## Goal
- 완료 기준 (TASK.md 그대로): 운영 지표(토큰수·레이턴시)와 같은 자리(ops.json·report·ops_history)에 모델별 토큰 단가로 계산한 비용(합계·요청당 평균·모델별)을 남긴다. 단가 없는 모델은 지어내지 않고 "단가 미설정"으로 표시. pytest.
- Baseline: `evals/reports/ops_history.jsonl` 164줄 중 cost 기록 **0줄** (전부 null).
  원인 3가지 (코드 `evals/ops.py`는 T3-39에 이미 있음):
  1. `evals/pricing.json`의 HCX-DASH-002·HCX-005·HCX-007 단가 null (공식 가격표가 스크립트 렌더링이라 WebFetch·브라우저 텍스트로 못 읽음, 2026-11-23 재확인)
  2. 자체 호스팅 모델(현재 Qwen 27B 경량화, 이전 gemma) 단가 정책 없음 — Qwen은 pricing.json에 항목조차 없음
  3. 한 턴이 HCX(KRW) + gpt-4o-mini(USD)를 부르면 통화가 달라 합계를 버림 → e2e 기본 구성은 항상 null
- 추가 공백: Ragas 판정 LLM(gpt-4o-mini, 답변 품질 평가용) 토큰은 아예 집계되지 않음. 요청당 평균 비용 필드 없음(합계만).

## Idea
비용은 코드가 계산한다(단가표 × 토큰). 단가는 사용자가 확인한 값만 넣고 `_source`를 남긴다.
1. `pricing.json`에 `fx` (USD→KRW 고정 환율, 기준일 기록) 추가 → `row_cost`가 모든 통화를 KRW로 환산해 합친다. 원 통화별 금액도 `by_model`에 남긴다.
2. `summarize`에 `cost.per_request_mean` 추가, `append_history`에 `cost_per_request` 추가, report(md·html) 타일에 요청당 비용 표시.
3. Qwen 모델명을 pricing에 등록. 자체 호스팅 단가 정책은 사용자 결정(0원 / GPU 시간 환산).

## Option A — 단가 채우기 + KRW 환산 + 요청당 평균 (평가 대상 파이프라인만)
- 접근: 위 Idea 1~3. Ragas 판정 비용은 범위 밖.
- 예상 성능 향상: cost 기록되는 실행 0 → 앞으로의 모든 HCX/gpt/Qwen 실행 (e2e·agent·l1·l3). 저장된 T3-39 이후 run은 `--from-run` 재채점으로 즉시 비용 산출(tokens_by_model 있음).
- 실질 반영 이점: 핵심 지표 "요청당 비용·지연" 충족, T3-10 아키텍처 비교 표의 비용 열 근거.
- 비용·리스크: 1~2시간, LLM 0. 환율 고정값이라 실제 청구와 수% 차이.

## Option B — A + Ragas 판정 비용 별도 집계
- 접근: A + `RagasScorer`의 AsyncOpenAI에 httpx 응답 훅을 달아 `usage`를 모델별로 합산, ragas run의 ops에 `judge_cost`로 따로 기록(서비스 비용과 섞지 않음).
- 예상 성능 향상: A + 평가 1회 비용(판정 포함) 0 → 측정. 서비스 요청당 비용은 A와 동일.
- 실질 반영 이점: "평가를 돌리는 데 얼마 드나"까지 발표 근거. 판정 캐시 적중 시 0원으로 보이는 점을 함께 표시.
- 비용·리스크: +반나절. ragas 내부 호출 경로(llm_factory·embeddings)에 의존 — 버전 바뀌면 깨질 수 있음.

## Option C — B + 과거 run 일괄 소급 + 서비스 OTel 비용 메트릭
- 접근: B + 저장된 `evals/reports/*/results.jsonl`에서 ops를 다시 계산해 ops_history에 소급 줄 추가, 서비스(`tracing.py`)에 `kosis.llm.cost` Counter 메트릭.
- 예상 성능 향상: 과거 비교 기준(T3-28·T3-32·T3-43 등) cost 0 → 일부(T3-39 이후 형식 run만; 이전 run은 모델 합쳐진 토큰이라 불가).
- 실질 반영 이점: 시간 추이 그래프. 운영 대시보드(Jaeger/Prometheus)에서 비용.
- 비용·리스크: +1일. 소급분은 단가 시점이 달라 오해 소지, 메트릭은 평가와 이중 계산 주의.

## Recommendation
옵션 A. 핵심 지표(요청당 비용)를 가장 단순하게 채우고, 과거 run은 기존 `--from-run`으로 필요한 것만 재계산하면 된다. 판정 비용은 서비스 비용이 아니라 우선순위가 낮다.
